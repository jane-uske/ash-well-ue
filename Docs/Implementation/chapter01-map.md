# 第一章《下井》：连续地图 v01

2026-09-07。用户确认概念图风格与场景顺序后，使用 Blender MCP 制作模块，使用 UE 5.8.2 原生 MCP 项目工具导入、摆放并保存关卡。当前交付是一张从生活区走到 Boss 和升降机的可玩地图，独立打包仍按用户要求暂停。

## 体验入口

双击 `Scripts/launch_chapter01.command`，或在项目根目录执行同名脚本。脚本以 `-game` 打开开发版游戏窗口，依赖本机 UE 5.8 与已编译项目模块，不需要在编辑器里点 Play。

WASD 移动、鼠标转向；E 修泵、送电、读取记录及启动升降机；左键攻击，空格闪避，Tab 锁定；R 重试；Esc 暂停与设置，暂停时方向键调节。

到达检修站之前，R 从配给街重新开始；到达后，R 回到检修站入口。此进度仅保留在当前运行会话中，关闭游戏重新启动会回到配给街。

地图路径：`/Game/AshWell/Chapter01/L_Chapter01_Descent`。旧单场战斗仍由 `Scripts/launch_combat.command` 启动。

## 实现边界

`AshWellChapterDirector` 负责修泵开门、区域提示、同伴沿栈桥路线跟随以及检修站检查点。战斗的伤害、体力成本、攻击与闪避时序保持原规则；进入站区前阻止锁定远处 Boss。同伴到站后停止行走动画。新增长地面使用世界坐标纹理，避免拉伸；灯光显式使用流明。修正地面和已有玩家锤子粗糙度的 Metal 采样类型，锤子重新导入的边界和握持轴与原记录相符。

原 FirstDescentIntro 地图未覆盖，新地图从模板创建。当前检修站战斗的代码仍为共享实现，没有复制一套 Boss 状态机。改动前的代码、配置和脚本快照在本机 `Saved/Chapter01/before-chapter01.zip`；快照不含 Content，不能当作完整资产备份。

## 实机验证

- 原生 Development 编译成功；原玩家规则 21 项源码回归通过。
- 从街道初始出生，经修泵和开门，使用实际 CharacterMovement 走过全部路线并到站；路线索引 18/18，无卡住或落井失败。转角平台曾阻挡下坡，修正平段与坡段衔接后重跑通过。
- 同一次路线运行接续既有战斗机器人：20 次有效击中，Boss 800 生命归零，二阶段触发；读取记录，升降机完成，`slice_completed=true`。
- 单独一轮从配给街走入站区、承受攻击死亡，再调用与 R 同一重启逻辑；重启位置 `(3180, 980, 90)`，玩家生命/体力 100，Boss 生命 800，三招状态和结束记录重置。机器人在重试时会自动触发送电。
- 图片均为 1600 × 900 实际游戏画面，见 [验证目录](../Verification/Chapter01/README.md)。概念图不是实机证据。

完整流程成功记录里的 `route-complete.json` 每秒写一次，最后一帧仍是升降机途中，`chapter_complete=false`；最终完成状态由同次运行退出前写入的 `fight-ending-complete.json` 中 `slice_completed=true` 证明，不将前者改写成成功。

本轮未重跑此前整套战斗专项镜头探针，未完成新地图 30 分钟性能验收，也没有把机器人测试当作真人试玩或难度验证。

## 后续细节

地图空间和主要交互已连通，视觉仍是第一版：住宅重复度、居民差异、人物与道具的近景精度、同伴脚步衔接及接触动作还需打磨。配水修复当前是交互和状态变化，没有完整扳阀动画；疑似人影目前由字幕引导，没有新增人物演出。守井者停机后沿用已有台词/服役记录，还没有完整制作陆衡救援、闻舟照看伤者的剧情表演。第二章的无名工区尚未建造。

## 临时胜利后预览

用户请求帮助通过 Boss、亲自查看后续时，可在非 Shipping 开发版使用 `Scripts/launch_chapter01.command -ChapterAfterBoss`。这会在本次进程首次进入章节时回到检修站、满血并触发守井者正常停机/胜利流程，保留玩家输入、记录和升降机交互。不会自动读取记录或启动电梯，不改变常规启动参数与战斗数值；本次会话按 R 仍会正常重试 Boss。
